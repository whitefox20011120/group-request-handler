# MaiSaka 加群申请处理插件 

# 记得一定要给麦麦管理员权限！！！

> QQ 加群申请自动化处理插件。它可以将接收到的新加群申请及申请人详细资料推送到通知群内，并允许管理员或群主直接在群内快捷同意或拒绝。
> 有问题请提issue

## ✨ 主要功能

* **详细资料与头像推送**：收到申请后，自动抓取申请人的详细 QQ 资料（头像、昵称、目标群号、性别、年龄、等级、个性签名、验证消息等），并附带头像一起推送到群内。
* **快捷指令审批**：配置的全局管理员或对应群的群主/管理员，可以通过简单的群聊指令（`/同意入群` 或 `/拒绝入群`）快速处理加群申请。
* **黑名单自动拒绝**：配置的黑名单用户加群直接决绝

## ⚙️ 配置说明

插件首次加载后，会在 MaiBot 的配置面板中生成对应的设置项。

### 1. MaiBot 插件端配置

在机器人的配置界面（或配置文件）中，您可以按模块设置以下内容：

```
# 管理员设置
admin_qqs = 麦麦管理员 QQ 号列表。加群申请会推送到通知群，且只有此列表中的管理员或该群的群主/管理员才能使用审批指令。

# Webhook 设置
 host = 监听 NapCat HTTP 上报的本地地址，默认 `127.0.0.1`。
 port = 监听端口，需要和 NapCat HTTP 客户端配置中的端口一致，默认 `18081`。
 path = HTTP 路径，NapCat 的 URL 应填成的路径，默认 `/maibot/group_request`。
 secret = 可选 secret，对应 NapCat 「HTTP 客户端」的 token，留空则不校验。

# 申请通知设置
 send_avatar = 推送加群申请通知时，在文本上方附带申请方的 QQ 头像，默认开启。
 avatar_size = 头像尺寸（像素），常用值: 100/140/640，默认 `640`。

# 欢迎语设置
 message = 同意入群后，在群内 @新成员 并发送此欢迎语，留空则不发送。

# 自动撤回
 enabled = 同意入群后，自动撤回 bot 之前发送的加群申请通知消息。
```


### 2. NapCat 端配置

为了让插件能收到加群申请，您需要前往 NapCat 的配置界面，添加一个 **HTTP 客户端 (HTTP Post)** 推送目标：

* **URL**: `http://127.0.0.1:18081/maibot/group_request` （请根据您在插件中配置的 host, port, path 进行替换）。
* **Token / Secret**: 如果您在插件的 `webhook.secret` 中填写了密钥，请在这里填入相同的值；如果插件端留空，则此处也留空。

## 🚀 使用方法

当有用户申请加入群聊时，机器人会在群内发送类似如下的推送消息：

```
> [QQ 头像图片]
> 📨 收到新的加群申请
> 申请人QQ: 123456789
> 昵称: 张三
> 目标群号: 987654321
> 性别: 男
> 年龄: 22
> 等级: 64
> 个性签名: 麦麦我喜欢你
> 验证消息: 麦麦我想玩玩你的
> 同意入群请发送：/同意入群 123456789
> 拒绝入群请发送：/拒绝入群 123456789
```

**管理员/群主审批指令：**

| 指令 | 说明 | 示例 |
| --- | --- | --- |
| `/同意入群 <QQ号>` | 管理员/群主同意指定 QQ 的加群申请 | `/同意入群 123456789` |
| `/拒绝入群 <QQ号>` | 管理员/群主拒绝指定 QQ 的加群申请 | `/拒绝入群 123456789` |

> **注意：** 审批指令必须在**群聊上下文**中使用，且发送者的 QQ 必须是全局管理员（`admin_qqs` 列表中）或该群的群主/管理员 (`owner` 或 `admin`)。

## 📁 目录结构与数据存储

插件会在自身目录下自动生成一个 `data` 文件夹用于持久化数据：

* `data/state.json`: 用于记录**待处理的申请列表**和**已推送的事件 Flag**。这保证了即使机器人重启，之前的申请依然可以用指令处理，并且启动补漏不会重复推送已经通知过的申请。无需人工干预此文件。
